# Task Handoff（跨平台任务交接）

HANDOFF 指业务项目中的 `docs/HANDOFF.md`（任务交接记录），用于持久保存当前目标、实际进展、决策、测试证据、风险、下一步和 Git 状态。本 Skill 是该文件的更新流程，不是聊天记录同步器。

## 何时使用
任务阶段完成、工作暂停、重要决策产生或从一种 AI 平台切换至另一平台之前。

## 操作
1. 读取该项目 `docs/HANDOFF.md`、Git status/diff（工作区状态和文件差异）以及最近测试结果。
2. 更新目标、状态、决定、关键变更文件、真实验证结果、未解决问题、下一步和所采用的规范基线。
3. 记录 Git 分支/commit（版本提交标识），若尚无提交须说明；推测或未验证项明确标记。
4. 不复制聊天流水或冗长日志，不写认证令牌、密码与敏感数据。
5. 接手 AI 首先核对实际文件和测试证据，不盲信交接记录中的旧状态。

## 输出
简短、可独立理解的任务交接文件；有长期影响的架构决定另存 ADR（Architecture Decision Record，架构决策记录）。

## 更新频率
只在重要交接点滚动更新，不要求每条聊天或每次工具调用都改文件。

## photo_system 的公开仓库约束
- 本仓库是公开 Git 仓库；`AGENTS.md` 为本地私有文件，受 `.gitignore` 排除。
- 公共 `docs/HANDOFF.md` 不复制私有规则、私人设备路径、凭据、密钥、环境特有的内部参数或未获准公开的信息。
- 新环境如无法获得本地 `AGENTS.md`，必须说明完整规则尚未加载，并由项目负责人通过授权渠道提供；不能假设克隆 GitHub 后规则完整。

## 发布交接
- 交接文件仅保留当前状态、正式设计入口、可复核的验证证据和剩余风险，不累积逐轮讨论。
- 正式变更验证后 Squash Merge 到 main；开发提交及过程归档仅保留本地，GitHub 只同步 main。
- 发布前检查最终文件与待公开历史的内容、提交说明及作者信息，不默认改写已经公开的历史。
